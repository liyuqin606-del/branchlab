# 反例驱动的训练诊断程序进化

2026-09-05 · 设计候选，未实现、未运行训练 · 基于 CS336 + Marin 的个人研究项目

## 结论

建议把创新对象定为：**训练系统自动构造短诊断实验，发现自己原先看不出的训练状态差异，并让后代继承这些诊断方法。**

项目名可用：**从零实现 Transformer，并研究训练诊断程序的自我改进**。

这一版用“如何获得决策所需的新证据”推进原来的学习率控制器。工程底座仍是从零语言模型、完整训练恢复、KV cache、性能测量；研究贡献落在可执行诊断方法的发现与复用。

本轮初筛没有建立原创性证明。主动实验设计、反例引导合成、自动调试和改进器自修改均有成熟先例。本方案值得验证的是它们在训练系统中的一个具体算法组合及其效率边界，不能仅凭组合或名称声称新颖。

## 1. 问题：同样的训练症状，可能需要相反的修复

假设两次训练的 loss、梯度范数和近期下降速度相似。一次可能在数据分布变化后保留了不适合的动量；另一次可能遇到数据顺序聚集，而保留动量反而有用。直接根据症状选择“降学习率”或“重置动量”可能选错。

这只是待检验的示例，不能预先把状态标成某种唯一根因，也不能保证两个具体状态确实要求相反的修复。最终标签来自实际后续训练效果，而非人写的故障名称。

核心假设是：**有些训练决策错误来自现有观测无法区分状态；自动合成短对照实验可以补足这些观测，而且比逐项尝试完整修复更便宜。**

只要完整免费日志或优化器统计就足以解决问题，这条假设就会减弱。因此所有方法均可使用同一套低成本日志、配置与状态摘要，不能故意删掉强基线能用的信息来制造盲区。

## 2. 可执行机制

系统保存两个对象：

- 训练状态 `s`：权重、优化器、scheduler、RNG、数据位置，以及当时允许看到的数据。
- 改进器 `U_g`：诊断程序库、程序生成/选择策略、修复选择器和第 g 代历史。

### 步骤 A：找出当前方法分不清的失败对

在发现集上用实际训练分支评估一个小修复菜单，包含继续原训练、不改、降低学习率、有限动量处理、恢复基准数据顺序。修复菜单的各操作及其额外成本在实现前锁定。

将“当前观测近似、当前策略给出同样建议，但实测较优修复不同”的两个状态组成反例。只有修复差异超过重复测量噪声才保留为明确反例；不稳定情况保留为不确定记录。高损失反例优先，避免主要优化无关紧要的微小区别。

反例构建使用训练阶段的实际反馈；最终测试状态的最优修复和未来训练效果始终不提供给改进器。

### 步骤 B：为反例合成新的诊断实验

合成目标是一个可执行程序，明确指定：克隆哪些状态、施加什么短扰动、跑几步、计算哪个差分统计量。不是只学习“何时调用现有探针”。

首版使用有限语法，避免任意代码搜索：

```text
probe := clone + intervention + short_run + contrast
intervention := no_change | lr_multiplier | first_moment_damping | reorder_known_batch_block
short_run := 4 | 8 | 16 optimizer updates
contrast := loss_delta | update_alignment | recovery_slope
```

限制程序最多两个分支、每分支最多 16 步；由短原语组合产生新程序。若需四格交叉实验，则算作两个探针并计入全部成本。数据重排只作用于训练系统此时确实已可取得的固定小批次块，不访问最终测试文本或实际尚不可知的未来样本。

例如，系统可以尝试：“从相同权重和二阶矩出发，分别保留一阶矩或把一阶矩乘 0.5；用相同批次运行 8 步，比较更新方向和开发 loss 的变化。”这只是候选程序示例，不能预设它有效。

每个探针均在克隆状态上执行，诊断结束后恢复原始状态，再开始实际修复。探针分支不偷偷成为额外训练后的部署起点。完整恢复与代价记录是实验语义，而非算法创新。

### 步骤 C：按实际修复收益评价探针

设 `L_s(a)` 为在状态 s 应用修复 a、用固定后续预算训练后的独立开发 loss；`a*` 是受限修复菜单中的实测较优动作。探针 p 产生的观测被修复选择器映射为 `a_hat`。

用于开发阶段的目标为：

\[
\operatorname{Regret}(p)=\mathbb E_s\big[L_s(\hat a(p,s))-\min_{a\in\mathcal A} L_s(a)\big].
\]

在固定诊断预算下减少 regret，再在完整计算预算下比较最终 loss。regret 只是受限菜单和指定训练期限下的损失，不是对全局最优训练算法的误差。

信息增益、反例分离率可作为候选筛选指标，最终入库由未用于合成的开发状态上的修复收益决定。避免“分类器更会辨认故障名字，却没有改善训练”。减少决策损失的实验设计已有先例，也不单独作为新颖性主张。

### 步骤 D：继承并改进诊断方法

每代新增的程序在其他发现状态上执行，形成新特征。保留有效程序，合并重复程序，记录其适用范围和失败例；下一代从更新的程序库与策略出发。

具体可学习对象包括：如何选择待解决的反例、如何重组探针原语、何时停止增加诊断成本。保留原始搜索器作为冻结对照。

为避免“反例只是提示词”的空泛做法，首个算法版本明确采取：按现有选择器的修复 regret 排序反例 → 对反例产生候选程序 → 在固定小发现集上执行 → 以保留开发集上的增量修复收益晋级 → 更新程序库。程序产生器可以先用受限枚举或小规模搜索实现。

如果同语法的简单枚举已经同样有效，就保留程序库工程成果，不宣称发现了更强的学习算法。

## 3. RSI 要增加哪一步证据

仅继承工具库、累积日志或重训一个分类器，支持的是自适应诊断或经验复用。

要研究递归改进，必须让 U 的诊断程序生成/选择策略也成为被修改的对象。修改后的 U1 要在相同预算、相同初始程序库和相同新任务下，比 U0 更善于产生有效的下一代诊断程序。

因此分别测量三个量：

1. **修复能力：** 给定同一诊断程序库，系统是否更少选错修复？
2. **实验发现能力：** 从同一空白/固定库开始，系统是否更少花费就能发现一个可迁移的有效探针？
3. **递归贡献：** 新改进器产生的下一代，是否比旧改进器产生的下一代更好？这种差异是否因继承的生成/选择策略而出现？

递归实验交叉使用旧/新改进器与旧/新程序库，固定历史数据与每个候选的可见信息。另设每代用全部相同数据重新搜索的基线，防止将额外数据量当作继承收益。

冻结评分器、预算计数器与最终测试集合。基础 LM 本身不承担诊断程序生成，除非以后另做并实测这项能力；使用外部冻结代码模型时必须单独说明和计费。

若只有第一项成立，称训练诊断系统；第二项成立可称诊断方法的自我改进；第三项也经对照支持，才讨论限定任务上的递归改进证据。

## 4. Stanford 资源怎样实际参与

**CS336** 提供自建 Transformer、训练循环、恢复、梯度与性能分析的底座。研究代码主要是训练工程，不需要先搭建通用聊天 Agent、RAG 或网页平台。

**Marin** 用于从真实公开失败中挑选问题类别。例如 [32B 回顾](https://github.com/marin-community/marin/blob/main/docs/reports/marin-32b-retro.md) 描述数值不稳定、恢复尝试与数据打乱问题；这些事件提供任务动机，不能假装小模型复现了同一规模机制。

**Delphi** 的公开表用于规模和配方敏感性分析；它们没有本次已验证的逐步干预字段，不给探针合成提供虚构的反事实反馈。研究中所有对照分叉由本地可恢复小模型产生。

实验区分三层：注入的受控扰动、自然出现的小模型问题、Marin 大模型公开案例。前一层的成功不能自动提升为后一层复现。如果仅有合成扰动结果，结论明确限定为受控训练场景。

## 5. 首个小实验：先杀死不值得做的方向

先保留一个从零小型 Transformer。调试可用更小配置，研究展示目标约 20M 参数；不为追求这一数字先扩大算力。

**第一道检查不学习新 Agent：** 选两个实际可产生不同修复收益的训练条件，以三条独立 seed 轨迹构造配对起点。比较免费日志/状态统计与两个手写短探针，观察诊断是否可能减少选错修复。短步探针的结论另用不重叠批次、较长的后续训练评估验证，避免只适配一个短期限。

在没有潜在诊断价值时立即停止。如果有价值，再收集按 seed、数据来源和问题组合隔离的发现/开发/测试状态，进行探针合成。不能把六个起点同时用于合成与验证，也不能将同一 seed 的多个切片视为独立重复。

探针上限建议先取总预算的 10%，这是待测的设计上限，不是成本结论；超过上限直接不诊断并采用基线。若所有有效探针都太昂贵，则不能宣称省算力。

| 必需比较 | 排除的解释 |
|---|---|
| 完整免费日志和状态统计 → 修复 | 其实无需主动实验 |
| 最佳手写短探针 + 同修复选择器 | 人写两条规则就足够 |
| 依次短跑各修复 / successive halving | 诊断不如直接试修复 |
| 相同语法、历史、执行缓存和搜索预算的随机/枚举/BO 搜索 | 新方法只是有限搜索空间内换一种命名 |
| 固定程序库，仅更新调用策略 | 收益来自调用策略而非新实验的合成 |
| 反例驱动的程序合成与继承 | 主方法 |

与枚举和 BO 的比较优先于声称“自动发明”。若候选空间很小，枚举是强而合理的解法。

主结果是同硬件、同总训练/诊断预算后的独立评估 loss；再报告修复 regret、失败率、达到同等恢复效果的总耗时与曲线。将公共实验数据获取、所有失败候选执行、程序搜索、代码模型调用、编译与检查纳入全生命周期成本，另外报告部署时成本。

若为评价准备了全动作或全探针结果表，可仅给审计器使用。搜索器按真实已请求的结果逐步揭示，所有方法共享相同缓存规则；测试期禁止免费的全表查询。

## 6. 与近邻逐项比较

本轮核验以一手摘要及下列已读取的方法段为依据，属于有针对性的初筛，不代表穷尽检索或独立复现。

| 来源 | 核验层级 / 已覆盖内容 | 本项目仍需证明的差异 |
|---|---|---|
| [AutoTTS](https://arxiv.org/html/2605.08083)，2026-05 | 方法 2–3：在预收集推理轨迹和探针信号上合成控制器 | 自动构造新的训练干预与测量程序，而非只选择何时读已有信号 |
| [DoVer](https://arxiv.org/html/2512.06749)，2025-12，ICLR 2026 | 方法核查：Agent 系统 checkpoint、干预、恢复、差分效用 | 新诊断实验的发现效率、跨训练状态复用及其代际效应；不能把克隆和干预本身当创新 |
| [Hyperagents](https://arxiv.org/abs/2603.19461)，2026-03 | 摘要与方法结构：元改进器可以修改自身 | 训练诊断程序这一具体可迁移对象的机制收益；自改代码并不新 |
| [Step-DAD](https://arxiv.org/html/2507.14057)，2025-07 | 方法核查：在实验中继续更新设计策略 | 固定实验空间内学习选择不够，需证明生成新程序及反例目标有价值 |
| [GoBOED](https://arxiv.org/abs/2605.26093)，2026-05 | 摘要：直接面向后续决策目标优化实验 | 用修复 regret 评分本身不是创新 |
| [反例引导的自动机学习](https://sws.cs.ru.nl/publications/papers/fvaan/CEGAR12/FM.pdf)，2012 | 摘要/引言：反例驱动改进观测抽象 | 反例细化并非新原理；需要与同语法合成基线比较 |

因此，当前只提出下面这条**待验证贡献**：

> 在训练状态的修复歧义上，用反例指导有限诊断程序的合成，并通过跨状态的真实修复收益筛选可继承程序，能否降低下一代训练改进器的试验成本？

这个贡献包含一个明确可失败的学习与程序合成问题，而不是“加 Agent”“加记忆”“加 RSI”的功能清单。

## 7. 本轮淘汰的主创新表述

- **按未来可塑性选 checkpoint：** [Weight Decay Improves Language Model Plasticity](https://arxiv.org/abs/2602.11137) 和 [Local Redundancy](https://arxiv.org/abs/2607.13432) 已有很近的路线。只改指标名称不够。
- **移植一阶矩并测未来价值：** [Stored in Optimizer State, Valued by Later Training](https://arxiv.org/abs/2608.20442) 已提出同参数状态干预与未来价值变化。
- **完整优化器状态指导短期训练干预：** [Delayed Optimizer-State Transport](https://arxiv.org/abs/2608.24593) 已直接研究前瞻选择。
- **优化器训练自身：** [Training Learned Optimizers with Randomly Initialized Learned Optimizers](https://arxiv.org/abs/2101.07367) 已有明确先例。进一步选择“后代可改进性”仍可能属于高阶元学习，且小项目嵌套训练成本更高，因此本轮不作为主推。

以上淘汰的是宽泛创新表述，不代表这些论文结论已被本项目独立验证，也不排除将其方法作为基线。

## 8. 晋级与放弃标准

- 同等输入和预算下，免费状态统计或固定专家探针已匹配收益：不主张学到新诊断能力。
- 同语法枚举/BO 已匹配发现效率：不主张新搜索/学习算法优势。
- 新程序仅识别人工注入标签，不能改善实际后续训练：淘汰机制。
- 诊断的额外计算大于节省的试错成本：淘汰省算力主张。
- 去掉程序继承但保留同历史后结果相同：不主张继承收益。
- 新 U 不能更有效地产生后代：不主张递归收益。

下一项具体工作是上述“免费日志与两个短探针”的信号检查；本轮未运行该实验。成功后才值得实现和比较自动程序合成器。
