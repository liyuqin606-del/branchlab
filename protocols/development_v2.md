# v0.2 development protocol — not a confirmation

Frozen before collecting development outcomes. All v0.1 states/windows are development evidence. This run uses new development seeds 8–14; their results can select designs but will never confirm them.

Train each ~1M model for 160 updates at fixed LR 0.001 after 10-update warmup. Save native states at steps 40/80/120/160. Per seed retain eight declared conditions: native at 80 and 160; current weights/second moment with first moment copied from 120 or 80; norm-matched first moment from 80; half-current/half-step80 first moment; LR half or double on the native160 state. Moment transplantation is a controlled intervention, not an observed Marin failure. Expose age, blend fraction, norm-matching scale, LR, recent losses, and all computed cheap gradient/moment summaries to every policy. Preserve native controls in all aggregate denominators.

All policies compute the current training gradient once (one normal training update's 3 proxy units). Cheap policies receive it too. Materialize keep/half-LR/zero-first-moment candidate optimizer steps using the same clipped gradient and origin state. A chosen candidate commits this first update, with correct moments, RNG and data cursor, and continues normally. Other materializations require tensor arithmetic but no extra model backward/forward; record their physical count separately.

A probe contrasts one alternative candidate with keep on the next known training batch at offset 1/2/4/8. Each pair costs 2 model-forward units. Data is the already available training corpus; no evaluation text is used in the probe. All candidate-generation metadata remains visible to cheap policies. Two probe readouts share cached physical forwards during benchmark construction; replay and actual costs are separate.

The deployment cap is 224 forward-batch equivalents. Reserve 32 for final dev and test evaluations (16 fixed 256-token batches each). A no-probe policy gets 64 total updates; one pair probe leaves 63. This development run collects dev loss only, on the 4,096-token window starting at dev offset8192; no test loss is read. Preserve costs reserved for the eventual test evaluation. Root curves contain both step63 and64 losses for every repair. Actual corpus forward/backward counts, candidate materializations and elapsed time are recorded. This cost proxy excludes small tensor-arithmetic/predictor costs and is not a wall-clock speedup claim.

Fit repair and value-of-information heads on discovery seeds8–11. Gate targets use leave-one-training-seed-out predictions, so an episode cannot predict its own usefulness through a head fitted on its seed. The gate sees only free logs before deciding whether to acquire a probe. Promote the complete policy on development seeds12–14 using loss at the actual remaining horizon, not fixed-horizon regret. Random/enumerated/counterexample ordering share head/gate model and probe-cell cap; reveal costs and actual measured search work must be reported separately. Fixed-expert and no-probe policies are included.

Control shorter-training artifacts with logs-only63 and logs-only64 baselines plus a logs-only joint action/horizon selector. If shortening training explains a gain, it is not diagnostic information value. A failed mechanism screen remains NOGO. No audit seeds or confirmation statistics are used here; follow GOAL.md before any later confirmation.
