# BranchLab v0.1 frozen pilot protocol

Freeze this file and configs/pilot.json before collecting outcomes. This is a timestamped local protocol, not a registered study.

Eight independent initializations: discovery seeds 0–2, development 3–4, audit/test 5–7. Each seed trains its own ~1M Transformer for 120 updates on a deterministic seed-specific document order. Within each seed, clone the same full trainer state into clean, 4x learning-rate, and -3x first-moment conditions. These are controlled interventions, not natural Marin failures. A seed is the statistical unit; its three conditions are dependent.

Candidate repairs are keep, halve learning rate, or zero first moment. The other optimizer states, weight tensors, and training minibatches remain matched within an episode. Probe programs compare one repair with keep after 2/4/8 updates, measuring validation-loss contrast, training-loss recovery contrast, or update-versus-last-baseline-clipped-gradient alignment. The gradient reference is copied before restoring branches; it is the preceding completed training-step gradient, not a new backward pass. Free logs include the baseline validation loss, last training loss/gradient norm, learning rate, first-moment norm and first-moment/gradient alignment. Cache shared physical branches during table construction. Keep all cases, including cases where the passive baseline succeeds.

Fit repair predictors only on discovery records. Program promotion only uses development regret at a fixed 24-update repair horizon. All synthesis settings and candidate productions are fixed before test. Each branch evaluation uses one fixed batch (256 target tokens) from each local dev/test stream; this very small evaluation window is an explicit limitation. Final text evaluation uses a document-disjoint local test corpus; its scores cannot choose repairs or probes. Public TinyStories official-validation documents are repartitioned for this local experiment, which is not comparable to the official benchmark.

Use identical paid probe-cell budgets for counterexample ordering, random ordering, and enumeration. Compare no-probe prediction, a prespecified expert probe (lr_half:4:loss_delta), and direct short-trial repair selection. Report a full-enumeration reference separately when it consumes more search. Do not call it budget-matched if the actual query budget differs.

Primary engineering comparison: final test cross-entropy under at most 160 forward-batch-equivalent units per state. A training update costs 3 units (one forward plus approximate backward cost), a fixed-size evaluation costs 1. A two-branch probe conservatively costs 2*(3*h+2), including before/after measurements. Repeated readouts are charged separately. Spend the remaining units on the selected repair from the untouched starting state; include two final evaluations and report unspent units. This is a transparent analytic cost proxy, not measured FLOP equivalence or a wall-clock speedup claim. Report physical collection wall time and all table-construction work separately; offline replay savings do not erase data collection costs.

Supporting metric: repair selection regret at the fixed 24-update development horizon. Report per-seed differences; three audit seeds are a feasibility check, not a powered significance claim. Failure outcomes remain in the denominator; nonfinite outcomes block positive claims.

Mechanism gate: lower fixed-budget final test loss than passive, fixed-expert, and equal-search-budget alternatives, with consistent paired directions across audit seeds. If it fails, publish a negative/inconclusive pilot. Library inheritance is implemented; the synthesizer itself is fixed. Full recursive self-improvement is not tested and must not be claimed, even if this pilot succeeds. A later recursive experiment requires a new frozen protocol and distinct generation/test tasks.
