# v0.2 收集完成后的独立机制诊断

2026-09-05。只读分析 development 数据；没有新增模型训练、test 文本读取或确认性结论。详细数值、逐 seed 上界、逐探针相关性、实物核验见 `postrun_model_diagnosis.json`。

## 账目和冻结证据一致

- 56 个状态为 7 个 seed × 8 个条件，ID 完整且唯一；全部特征/标签有限，0 个失败。
- 冻结中所有源码和三个输入文件的 SHA256 均匹配当前实物。7 份历史各有 160 条记录；40/80/120/160 checkpoint 的步数、optimizer 计数、文档顺序和 token stream 哈希/游标均一致。
- 64/63 步的 336 个动作终点值与 episode `budget_losses` 精确一致。发布分析的各方法均值及逐状态路由值可独立重算。
- 物理计数符合代码：梯度 batch 11,760；普通 optimizer 更新 11,704；共享梯度的候选 optimizer 运算 168；训练文本探针 forward 672；development 评估 forward 5,376。训练 token 3,010,560，近似前向单位 41,328。
- 每状态只有一次共同第一梯度，却有三次候选 optimizer 算术。候选都做 4 个偏移时实际是 12 个 forward；把 8 个逻辑 pair 单独定价为 16 单位只是保守 replay 账，不能混称实际执行次数。

19/24 development 状态存在某种全知净预算改进机会，但平均上界只有 0.00797；实际 gate 和动作预测都要损失一部分。不能把“19 个状态可改善”当成当前探针能识别 19 个状态。

当前 92 个免费特征对应 32 个 discovery 状态，实际独立轨迹仅 4 个。discovery 的 64 步 oracle 动作计数为 keep=8、lr_half=22、momentum_zero=2；development 为 7/9/8。原发现集很少展示“reset 最优”，可能限制跨 seed 泛化。增加许多同轨迹条件不能替代更多独立轨迹。这支持检查低维/较强正则的廉价策略，并不证明换 head 一定会成功。

## 一步 next-batch 分数没有稳定对应长期动作排序

对每个 alternative，相应 probe 是“一步候选在后续训练 batch 的 loss − keep loss”，长期目标是“64 步 alternative dev loss − keep dev loss”。正相关才是原始方向直接一致。

- offset 1 的 LR contrast Pearson：discovery +0.140，development −0.511；moment contrast：−0.124、−0.204。
- 全部偏移的原始三动作排序，在 discovery 仅有 9.4%–18.8% 命中 64 步 oracle；development 为 16.7%–37.5%。只有 7 个独立 seed，这些是描述统计，不能包装成显著性判断。
- 若同时读取同一偏移下三个候选（实际 3 个额外 forward，仍落在 63 步预算），直接选 next-batch loss 最小：offset 1 的 development loss 为 3.421985，比 logs 64 步差 0.003546；其余偏移更差。
- JSON 同时列出按 seed/条件中心化的相关性。边际相关弱或反向不能严格排除条件信息，但目前没有证据支持“原始 next-batch 分数就是长期修复效用”。

## 状态结构和时间尺度仍需分开检验

在全部 7 个 seed 上，native160、stale40、stale80、matched_stale80、blend80 五种状态执行 momentum_zero 后，63/64 步结果精确相同。它们具有共同 θ、v、游标，唯一被移植的 m 被同一个动作清除；五个条件不能被视为五种独立的 reset 机制。

更关键的是动作作用时间不同：LR-half 在后续所有更新都持续存在；first-moment 清零是一次性操作。在 β1=0.9 下，初始 m 的直接递推系数经过 64 步为 0.001179，但这**不是**最终权重/loss 差异的界。一步探针可能偏好立即下降的动作，64 步目标却由持续学习率、未来数据和历史效应共同决定。现有文件只有 63/64 终点，尚不能证明“短期探针有信号但随后消失”。

## 下一步应补缺失证据

优先从已保存同一状态重放，不换种子或语料，补充 1/2/3/4/7/8/15/16/31/32/63/64 的同一 dev 窗口曲线，并要求 63/64 与原记录精确复现。这是 development-only 的机制寿命审计；全部新计算另记账，不能偷偷替换原 NOGO 的 horizon 或 gate。

依据该审计结果再选择设计：

1. 若探针仅能预测短期效用，可研究重复、间隔固定的控制决策，并把每次查询费用计入完整训练预算；不能直接把评价 horizon 缩短后称原目标成功。
2. 若不同 horizon 都缺少方向信号，应暂停当前一步 DSL，考虑已公开计划的真实数据混合变化，或跨 batch 梯度一致性；当前便宜特征和动作元数据继续全部开放。
3. 若信号存在而 head 失效，优先低维、按 seed 检验的学习器；不能通过隐藏 moment-age、LR 或候选一阶分数创造优势。

本次结论仍为 DEVELOPMENT_NOGO。上述分析不支持 RSI、诊断优势或确认性成功。
